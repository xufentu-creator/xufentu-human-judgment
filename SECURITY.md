# Security and Privacy

> Do not place private files, credentials, client materials, unpublished research, or confidential project content in public GitHub Issues, Discussions, pull requests, or repository folders.

The public Provenance Tool is designed to process selected files locally in the user’s browser. Under the normal workflow, the website owner does not automatically receive the files selected by the user.

Security, privacy, or accidental disclosure concerns should be reported privately to:

**[xufentu@gmail.com](mailto:xufentu@gmail.com)**

A useful report should briefly identify the affected page or file, describe what happened, include reproduction steps when relevant, and state whether private or confidential information may be exposed. Passwords, private keys, API credentials, client files, internal methodologies, and unpublished materials should not be sent unless a secure transfer method has first been agreed upon.

| Supported public component | Current version |
| -------------------------- | --------------- |
| Public research website    | `v1.6.0`        |
| Provenance Tool            | `v0.2.0`        |

Reports may concern unexpected network transmission, accidental exposure of private information, unsafe file handling, downloadable package errors, broken privacy notices, script injection, page manipulation, or incorrect access to restricted materials.

Questions about research interpretation, originality, authorship disputes, legal ownership, or copyright registration are not security vulnerabilities.

# 安全与隐私

> 请不要把私有文件、账户凭证、客户资料、未公开研究或机密项目内容放进公开 GitHub Issue、Discussion、Pull Request 或仓库目录。

公开 Provenance Tool 的正常设计是让使用者选择的文件只在浏览器本地处理。在正常使用流程中，网站所有者不会自动收到这些文件。

安全、隐私或意外公开问题请通过以下邮箱私下联系：

**[xufentu@gmail.com](mailto:xufentu@gmail.com)**

报告时可以简要说明涉及的页面或文件、实际发生的问题、必要的复现步骤，以及是否可能暴露私有或机密信息。在双方尚未确认安全传输方式之前，请不要发送密码、私钥、API 凭证、客户文件、内部方法论或未公开材料。

| 当前公开组件          | 版本       |
| --------------- | -------- |
| 公开研究网站          | `v1.6.0` |
| Provenance Tool | `v0.2.0` |

可以报告的问题包括非预期网络传输、私有信息意外暴露、不安全的文件处理、下载包错误、隐私提示与实际行为不一致、脚本注入、页面被操控或受限材料被错误公开。

研究观点、原创性、作者争议、法律所有权或版权登记问题不属于安全漏洞。
